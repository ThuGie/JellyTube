# JellyTube

A standalone Jellyfin plugin for YouTube discovery, private saved collections, managed downloads, and playback through Jellyfin's normal player.

**0.1 preview.** Targets Jellyfin 10.11.3+ within 10.11.x / .NET 9. The actual integration environment is Jellyfin 10.11.11 on Windows; physical Synology, ARM64 and TV-app testing have not been performed. See [validation](docs/validation.md).

## Standalone on Synology

The plugin runs extraction and downloads inside .NET with its bundled managed YoutubeExplode library. **No yt-dlp, youtube-dl, Python, Node, Deno, sidecar, container, or additional service is needed on your NAS.** The archive contains two managed DLLs and metadata/documentation, with no architecture-specific executable or native library.

Streaming passes through a compatible combined MP4 when YouTube provides one at comparable quality with the selected audio. Otherwise JellyTube serves separate tracks through DASH. Jellyfin's configured FFmpeg can remux or transcode for the client. Retained downloads use that same encoder to merge tracks without re-encoding. The Synology Jellyfin package must already provide a working FFmpeg. JellyTube never installs or replaces it.

## Install from the Jellyfin catalog

In **Dashboard → Plugins → Repositories → +**, add:

| Field | Value |
| --- | --- |
| Repository name | JellyTube |
| Repository URL | `https://raw.githubusercontent.com/ThuGie/JellyTube/main/manifest.json` |

Open **Catalog**, install **JellyTube**, then restart Jellyfin. The repository and [releases](https://github.com/ThuGie/JellyTube/releases) are public. Release archives, checksums and the catalog are generated by GitHub Actions.

## Install and configure

1. Download or build `JellyTube_0.1.0.0.zip`. Stop Jellyfin, extract it into a new **JellyTube** directory in that Jellyfin installation's plugin directory, then restart. Use the plugin directory belonging to your Synology package; package paths vary. Do not copy probe/test output into the plugin directory.
2. Open **Dashboard → Plugins → JellyTube**. Set the Jellyfin URL reachable by clients and the NAS itself, including any reverse-proxy base path. Set a writable, dedicated media root outside all existing shared library folders, and a storage budget. Overlapping library paths are rejected to preserve privacy. A Synology shared folder needs write permission for the Jellyfin package account. No package-specific filesystem path is hardcoded.
3. Click **Create shared library** once. If upgrading, choose **Set up shared library and migrate**. JellyTube copies native favorites and playback state for eligible accounts before retiring their old library entries. Accounts with library access can browse registered videos. Direct web playback and saved videos stay private, and the shared library is excluded from Recently Added.
4. Open Jellyfin Web and hard-refresh after installation; its header gains **YouTube**. Navigation is injected by JellyTube itself into the served index, without changing installed web files. **File Transformation is not required.** Existing plugins using File Transformation can coexist with this integration.
5. Search or paste a YouTube video URL. **Play** opens JellyTube's direct web player. **Play in Jellyfin** asks before registering the video in the shared native library.

YouTube API credentials are optional. Managed discovery supports video, channel and playlist search without a Google account. An optional server-side Data API key enables official video discovery with region/language and SafeSearch filters. Channel/playlist discovery uses the managed adapter. SafeSearch is not a parental-control guarantee, and it is unavailable for managed discovery.

## Included

- Video, channel and public-playlist search; direct video-ID/link lookup.
- Optional read-only YouTube account connections. For You and Following show subscription uploads for connected accounts, while disconnected accounts use JellyTube recommendations.
- Home feeds for recommendations, followed channels, topic discovery, Continue Watching, Watch Later, and Favorites. For You blends multiple interests with discovery and offers more results as you browse.
- Per-user favorites, Watch Later, named ordered playlists, followed channels, and recent channel uploads.
- Native video playback with separate audio/video ranges, format-aware source refresh, a bounded range cache and seekable segment timelines.
- Personal quality caps, layout, search preferences, recent-viewing preference and web queue preference.
- Native Jellyfin favorites and resume state are bridged to JellyTube once a native item exists. Changing favorites in either interface updates the other on refresh.
- Persistent managed download queue with cancellation, retry, restart recovery, per-user visibility, storage limits, atomic publication and explicit local-copy removal.
- Data export and separate JellyTube history clearing. Jellyfin's native history/resume settings remain under Jellyfin's control.
- Admin health, account access, per-user download permissions, shared-library setup, search budgets, minimum official SafeSearch and optional API key configuration.

## Connect a YouTube account

1. In Google Cloud, enable **YouTube Data API v3**, configure the OAuth consent screen, and create a **Web application** OAuth client.
2. Register the exact HTTPS redirect URI shown in **Dashboard → JellyTube**. It ends in `/JellyTube/YouTube/Callback`. Save the client ID and secret in JellyTube setup. If the Google app is in Testing, add each account as a test user.
3. Open Jellyfin Web using that same HTTPS base URL. In **JellyTube → Settings**, click **Connect YouTube** and grant read-only access on Google.

Each Jellyfin user connects separately. For You and Following start with a rotating set of up to 12 subscribed channels and load more as you browse. JellyTube leaves manual follows and personal collections intact when you disconnect. Google's API does not expose the personalized YouTube Home feed.

## Playback and native clients

Native clients use the shared JellyTube library and its native player. Custom YouTube discovery screens are provided by the web integration; a server plugin cannot add arbitrary search screens to every TV/mobile app. Browsers were tested at desktop and mobile sizes. A mobile browser test is not a physical Android/iOS or TV-app certification.

Shared playback defaults to a 1080p cap and selects resolution before frame rate. The per-user maximum resolution applies to downloads. JellyTube plays supported streams directly in Jellyfin Web and saves progress to the user's Jellyfin account. **Play in Jellyfin** opens the native player, which applies the device profile and the user's normal transcode/remux permissions. Native apps retain their own queue controls.

Public on-demand videos are the initial scope. Private, age/region-restricted, live/DVR, DRM and verification-required videos may be unavailable. Personal Google cookies are not imported. YouTube can change extraction behavior; fixes ship as a plugin/dependency update, not a new NAS command-line requirement.

Each stable STRM URL has a random owner/video-specific capability. Treat library paths and server diagnostics as sensitive. Capabilities are not general proxies: destinations come only from the validated extractor, and access is rechecked for disabled users and invalid library permissions. Jellyfin and its reverse proxy can log media URLs under their own logging settings.

## Automated releases

Push a four-part version tag, for example `v0.1.0.1`, or run the **Release** workflow with that version. GitHub Actions tests Windows and Linux, builds the portable ZIP, publishes the release, downloads and verifies the uploaded bytes, and updates `manifest.json`, `meta.json`, `build.yaml` and the source version on `main`. Existing catalog versions are preserved. Published version checksums are immutable; changed bytes require a new version.

```sh
git tag v0.1.0.1
git push origin v0.1.0.1
```

## Build and validate

Development only; none of these tools are NAS runtime dependencies:

```powershell
dotnet test tests/JellyTube.Tests -c Release
python scripts/package.py
npm ci
npx playwright install chromium
```

Optional live extraction probe:

```powershell
dotnet run --project tools/ManagedProbe -c Release
```

The integration scripts create a dedicated loopback-only server with its own data/config/cache directories. They do not deploy to an existing server:

```powershell
python scripts/live-test.py --server PATH_TO_JELLYFIN --ffmpeg PATH_TO_ITS_FFMPEG
python scripts/verify-integration.py
python scripts/verify-discovery-download.py
npm run test:browser
```

`scripts/restart-test.py` validates the recorded test-server identity and process path before restarting only that instance. Credentials and test media stay in ignored `artifacts/` files. The packaged archive is written to `artifacts/releases/` with a SHA-256 checksum. No repository is published automatically.
